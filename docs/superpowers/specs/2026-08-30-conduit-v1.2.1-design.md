# Conduit v1.2.1 — bug-fix release

**Status:** spec, awaiting Chris's review.
**Predecessor:** v1.2.0 (Phase 7.5), released and installed 30 Aug.
**Baseline:** `origin/main` at `1443151`. **2464 unit / 0 skipped, 152 e2e.**

---

## Goal

Clear the three defects a user actually notices, close the last loose end from the logo
work, and find out how much of the test suite is not testing anything.

Nothing here adds a feature except item 3, which cannot be fixed without one. There is no
migration. If a task believes it needs one, that is a finding to report rather than
implement.

## Two corrections to the record, made before anything is built

**1. The GIF item is IN, reversing what the backlog says.** The backlog's v1.2.1 section
lists it as explicitly out, on the reasoning that it is "worth fixing where a payload-size

reasoning was mine and Chris overruled it: the fix is a few lines, it is the last loose end
from v1.0.1's logo work, and deferring a bounded fix to a discussion that may never be
scheduled is how small things become permanent. **The backlog section must be corrected as
part of this release**, not left contradicting this spec.

**2. "The intermittents have no known rate" was false, and I said it twice.** Playwright is
configured `retries: process.env.CI ? 2 : 0`, and a retried failure **is** reported — the
CI log for run `33311033649` carries a `flaky` line. So the rate has been observable in
every CI log all along. What is missing is that **nobody has ever aggregated it, and a run
containing a flake is green**, so it passes unnoticed. That makes item 5 a harvesting job,
not an instrumentation one, and it is cheaper than billed.

## Scope — five items

### 1. The reply signature is silently lost on a cold accounts cache

**Evidence.** `composer.tsx` stamps its guard key **before** discovering whether a signature
exists. The reply path has a cold `useMailAccounts` — `seed.accountId` is set but
`sendableAccounts` is still `[]` — so the epoch-1 pass claims the key and appends nothing,
and the pass that runs when the accounts arrive returns early on that same key. A warm cache
hides it completely, which is why it has never been reported in use.

**Fix.** Stamp the key only once a signature has actually been found.

**The risk, and it is the reason this item is written up at length.** The fix moves the
signature append to a pass **after** the caret placement. That is exactly the case
`rich-text.tsx`'s `updateSelection: false` exists to survive. Today that option is
load-bearing only on the account-switch path, which is where it is tested; after this fix it
is load-bearing on the **reply** path too. **Verify that guard still holds before shipping
the reorder.** If the ordering is ever reversed again, fix the option's test first.

`composer.tsx`'s pending-body-focus comment currently asserts the append happens before the
caret placement. That is true on a warm cache only, and it must be corrected with the fix.

### 2. A deal's or project's Mail tab can compose with no recipient

**Evidence.** `rail/mail.tsx` resolves the contact through a **two-deep** query chain from a
deal or project tab (deal → contact), and `compose()` reads it at click time. A click before
both queries land seeds `to: []`.

**Fix.** Disable Compose until the queries it reads have settled. That removes the silent
wrong-recipient case, not merely the focus symptom that surfaced it.

**No test covers the deal or project tabs at all** — `composer-focus.spec.ts` uses a contact,
whose chain is one deep. **This item needs coverage written, not just a fix**, and the
coverage is the larger half.

### 3. `({{contact.pronouns}})` renders as empty brackets

**Evidence.** A contact with no pronouns renders the surrounding literal punctuation. Swallowing
a following space handles `Dear X Y`; nothing short of conditionals handles brackets or labels.

**This is the largest item in the release and it is a feature, not a patch.** The document
template engine already has `{{#path}}...{{/path}}` blocks; the **mail merge does not**.
Fixing this means porting conditional blocks into the mail merge. v1.1.0 deliberately ruled
to document the limitation rather than grow the template language mid-release.

**v1.2.1 is where that ruling is revisited — it is not overturned by default.** If the port
turns out to be larger than it looks, the right outcome is to say so and defer it again with
the measurement attached, not to ship a half-language. **Reuse the document engine's
implementation; do not write a second one.** Two template dialects in one product is a worse
outcome than the empty brackets.

### 4. The GIF dimension undercharge

**Evidence.** A 37-byte GIF whose logical screen descriptor disagrees with its frame data
under-declares its size to the logo limit. **The ceiling held** — the worst of four variants
ran at **59% of the 512MB kernel limit** and the other three were stopped outright. This is
hardening, not an open hole.

**Fix.** Fall back to the screen descriptor's dimensions instead of returning `null` on those
four shapes.

### 5. Harvest the real intermittent rates

**Not instrumentation — arithmetic on logs that already exist.** Every CI run reports its
flaky count; nobody has aggregated them.

- **Harvest every run on `main` and the merged phase branches**, and report the true rate of
  each of the three remaining intermittents: the Dovecot IDLE burst, the phone kanban
  `addStage`, and the `crm.spec.ts` "Other…" caret journey.
- **The Dovecot one is the only one that has ever failed CI outright** — once in 22 runs on
  the v1.2.0 branch — because the unit suite sets no retries. The two e2e ones have been
  passing on retry, invisibly, for an unknown period.
- **Deliverable is a number per intermittent plus a recommendation**, not a fix. If a rate
  turns out to be high enough to matter, that is the argument for scheduling the fix; if it
  is genuinely rare, that is worth knowing too.

### 6. The sweep: assertions that cannot fail

**Bounded to discovery plus cheap fixes.** Four are known, **every one found by accident**,
nobody having gone looking:

| Found | Assertion |
|---|---|
| v1.1.0 | three vacuous page-overflow checks — `documentElement.scrollWidth` had been blind since the first web commit, at every viewport |
| 7.5 / 4b | six of seven touch floors — `boundingBox().height` exists whether or not the control is on screen |
| 7.5 / 4b | the nav row's `scrollWidth >= clientWidth` — a value compared against itself |
| 7.5 / 4b | **the replacement I proposed for that line was also vacuous** — `scrollWidth` reports content overflow whether or not the box can scroll, so every arithmetic form of it is true by construction |

**That fourth row is the method.** A candidate is vacuous **until a mutation has been shown
to fail it**. Do not reason about whether an assertion can fail; break the thing it claims to
protect and watch.

**Scope:** sweep the e2e specs. Fix the dead assertions found. **File, do not fix**, anything
that turns out to be a real defect hiding behind one.

**The expected complication, stated in advance:** fixing a dead test can turn CI red for a
genuine reason. An assertion that has never been able to fail may be sitting on top of a real
bug — that is the point of looking. If it happens, report it and let Chris decide whether it
joins v1.2.1 or gets filed.

## Explicitly out of scope

- **Focus lost after any navigation that unmounts the focused element.** The biggest item on
  the deferred list, and out *because* of that: the fix is a route-change concern touching
  every page, and it would retire two hand-rolled cases in `inbox.tsx` and `board.tsx` at the
  same time. It earns its own release. Note it is **not** the five dialog roots — those are
  one entrance to it, and fixing them alone would make them the only navigations in the app
  that land anywhere, while row links remain the commoner path to the same pages.
- **Fixing** any intermittent. Item 5 measures; it does not repair.
- Any change to the four document types, time tracking, export/backup, or mail providers.

## Definition of done

- The three defects fixed, each with a test **shown failing before the fix**.
- Item 2's deal and project tabs covered — the coverage is the deliverable, not the fix.
- Item 3 either ported from the document engine or **deferred with a measurement**.
- Item 5's three rates reported as numbers.
- Item 6's sweep run, dead assertions fixed, real defects filed.
- The backlog's v1.2.1 section corrected to match this spec's item 4.
- Full unit and e2e green. Any count delta accounted for.
- **No migration.**

## Risks

1. **Item 3 is the schedule risk.** It is a template-language change wearing a bug's clothes.
2. **Item 6 can expand the release** by finding a real defect. Named in advance so the
   decision is Chris's rather than a surprise.
3. **Item 1 reorders two operations that another file's option exists to survive.** The guard
   must be re-verified, not assumed.
4. **The Dovecot intermittent gates CI**, at roughly one run in 22. If it fires during the
   release it will be re-run **and reported as a re-run** — never as a clean pass.
