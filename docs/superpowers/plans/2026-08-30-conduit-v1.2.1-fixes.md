## Conventions every task must follow

Carried from v1.2.0, where each was paid for at least twice.

- **NEVER RUN TWO MUTATING AGENTS IN ONE WORKTREE.** Reviews mutate — that is what an adversarial review is. Sequential, or one worktree each. This includes the coordinator's own commits.
- **Never restore a mutation with `str.replace("", ...)`** — an empty search string matches at position 0 and PREPENDS. Keep a copy of the original.
- **Do not `git checkout -- <file>`** to undo a mutation in a file you also edited this round.
- **Comments must be true, and a number must be measured at the moment it will be read.** v1.2.0 corrected nineteen false numbers before retiring the tally. The recurring shape was arithmetic over a moving target — the right measurement at the wrong moment, or the right set at the wrong granularity.
- **A COMMIT MESSAGE IS A COMMENT THAT CANNOT BE EDITED.** Three of those nineteen shipped in messages while the comments in the same commit were right.
- **Do not cite a line number in a file you are editing** — it rots inside your own commit. Name the passage.
- **Before committing a number, grep the file for the other places it is stated.** Two of the nineteen contradicted another sentence in the same file, written the same sitting.
- **A guard that reads source must be scoped to the construct it guards**, and its claim narrowed rather than its match widened: such a guard stops removal by omission and cannot stop tampering.
- **AN INSTRUMENT THAT HAS NEVER BEEN SHOWN TO FAIL IS NOT YET AN INSTRUMENT.** Five instruments on the v1.2.0 branch were reading something other than what they claimed. Break the thing an assertion protects and watch it fail, before trusting it to pass.
- Vitest from the repo root. Playwright locally via the hybrid loop. ASCII only. `git status` before every push. Targeted `git add`. Conventional commits with a `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer naming the model that wrote it.
- **No migration.** If a task believes it needs one, that is a finding to report.

### Task 1: The reply signature, and the guard the fix makes load-bearing

- [ ] `composer.tsx` stamps its guard key **before** discovering whether a signature exists. On a cold `useMailAccounts` — `seed.accountId` set, `sendableAccounts` still `[]`, which is the reply path — the epoch-1 pass claims the key and appends nothing, and the pass that runs when accounts arrive returns early on that key. **Stamp only once a signature has been found.**
- [ ] **THE FIX MOVES THE APPEND TO A PASS AFTER THE CARET PLACEMENT.** That is exactly what `rich-text.tsx`'s `updateSelection: false` exists to survive. Today it is load-bearing only on the account-switch path, where it is tested; after this it is load-bearing on the reply path too. **Re-verify that guard by mutation before shipping the reorder.**
- [ ] `composer.tsx`'s pending-body-focus comment asserts the append happens before the caret placement. True on a warm cache only. **Correct it with the fix.**
- [ ] A test that fails without the fix, exercising a genuinely cold cache.

#### Corrections to Task 1's premise, made while implementing it

Recorded here because the first commit, **`2c72be6`**, carries the wrong version of
two of them in a message that cannot be edited.

1. **The seeded cold state is UNREACHABLE, and the defect was latent rather than
   live.** The bug needs `seed.accountId` set while `sendableAccounts` is still
   empty. Only `conversation.tsx` sets it, from the same `["mail-accounts"]` query
   the composer reads, with an identical predicate -- so a seeded accountId implies
   a resolved cache. A review confirmed no other producer: no route parameter, no
   per-record default, no restored draft, no browser storage anywhere in
   `packages/web/src`, and no `resetQueries`/`removeQueries`/`clear()`. Measured in
   Chromium against the real component: seeded and cold, the body ended empty;
   unseeded and cold, the signature landed. The reorder still ships, because the
   first caller to seed an account id from somewhere else reopens it.

2. **`2c72be6` DELETED A TRUE COMMENT AND WROTE A FALSE ONE.** The
   pending-body-focus note said the cold-cache append lands on a later pass, after
   the caret, and that this is what `updateSelection: false` covers. That was true
   of v1.2.0 on the reachable path: with no seeded account the effect returned
   without claiming a key, the caret went in on epoch 1, and the append followed the
   accounts. `2c72be6` replaced it with "there was no later pass and no signature at
   all", which is true only of the unreachable seeded state, and claimed the reorder
   *made* the option load-bearing on the reply path when it **already was**.
   Restored in the follow-up commit, and measured both ways.

3. **A second, LIVE defect in the same effect, fixed here rather than filed.** The
   guard remembered only the last `(epoch, account)` pair, so A to B and back to A
   appended A's signature twice -- reachable from the From dropdown with two signed
   accounts, which is the fixture `e2e/composer-focus.spec.ts` already builds. Now a
   set of every pair signed.

4. **Two e2e journeys added**, since the "no reachable state to test" argument fell
   with correction 1: the duplicate above in `composer-focus.spec.ts`, and the
   reachable cold reply in `mail.spec.ts` (accounts response delayed, caret asserted
   above the deferred signature).

5. **THE COLD-REPLY JOURNEY SHIPPED VACUOUS ONCE, AND A THROWAWAY CI BRANCH IS WHAT
   CAUGHT IT.** `mail.spec.ts` cannot run in the hybrid loop -- it needs Dovecot and
   Mailpit, and the dev server has no container runtime and no test mailbox -- so the
   mutation was pushed to `tmp/mutation-check-task1` instead (run `33337463995`, since
   deleted). With `updateSelection: false` deleted, the account-switch journey failed
   three times out of three and **both reply-path tests passed**: they typed only
   BEFORE the append, and the append lands at the end of the document whatever it does
   to the selection. The fix is to type again afterwards and assert the two fragments
   are contiguous. **The pre-existing warm test at `mail.spec.ts` is vacuous for the
   same reason and is left alone here** -- on the warm path `focus("start")` runs after
   the append and resets the selection anyway, so nothing that test could assert
   separates the two spellings; that is Task 5's sweep, not this task's.

6. **The first version of that journey also failed OTHER tests.** Its route handler
   slept three seconds and then called `route.continue()`; a request still parked in
   the sleep at teardown throws "Route is already handled!" asynchronously, onto
   whichever test is running by then. It took down two different second-user tests on
   two runs and was reported as a flake in each. Now only the first request is held,
   and both continues swallow the teardown error.

### Task 2: A deal's or project's Mail tab composing with no recipient

- [ ] `rail/mail.tsx` resolves the contact through a **two-deep** chain from a deal or project tab, and `compose()` reads it at click time, so a click before both queries land seeds `to: []`.
- [ ] **Disable Compose until the queries it reads have settled.** That removes the silent wrong-recipient case, not merely the focus symptom that surfaced it.
- [ ] **NO TEST COVERS THE DEAL OR PROJECT TABS AT ALL** — `composer-focus.spec.ts` uses a contact, whose chain is one deep. **The coverage is the deliverable, not the fix.**

#### Corrections to Task 2's premise, made while implementing it

1. **A PROJECT TAB HAS NO CONTACT HOP AT ALL, so "deal -> contact from a deal or
   project tab" is half wrong.** `rail/mail.tsx` reads `deal?.contactId` from its
   OWN `dealId` prop, and a project tab passes none, so `useContact` is disabled
   there and a project composes with an empty To by construction -- settled or
   not. Measured in Chromium with every query landed and two seconds to spare,
   and confirmed on the wire: a project page requests no `/api/contacts/<id>` at
   all. What a project does have two deep is **project -> company**, which fills
   `context.companyName`; held open, `{{company.name}}` reaches the composed body
   unsubstituted. So there are two races, not one, and only the deal's is silent
   -- an unfilled name placeholder stays visible, an empty To does not.
   A **contact** tab is two deep into the same field (contact -> company), which
   is why the gate covers all four hops rather than only the deal's.

2. **THE PRESCRIBED FIX IS THE SHAPE v1.1.0 REJECTED, and it was not adopted as
   written.** "Disable Compose until the queries it reads have settled" cannot
   tell "not yet" from "never": measured, the naive form leaves the button dead
   for ever on every tab, because at least one of the four queries is always
   disabled and a disabled query sits at `status: "pending"` permanently in
   TanStack v5. Shipped instead as three states -- pending disables and says
   why, an error leaves Compose live beside an alert, and settled-and-empty is
   simply allowed. `document-form.tsx` already ships this shape for the same
   deal-to-contact data and writes out the same reasoning.

3. **A PHONE OVERFLOW ASSERTION WAS WRITTEN, MEASURED VACUOUS AND REMOVED.** The
   first draft asserted `toBeInViewport` on the new pending line and on the
   Compose button at 390. Geometry at that width: a 342px content box against
   175 + 8 + 89 = 272px of row, 70px of slack. Two mutations -- dropping the
   row's `flex-wrap`, then dropping it AND widening the line past the slack --
   both left the pair passing, because a flex child shrinks before its container
   overflows. Task 5's method, applied to this task's own new test.

4. **"NO TEST COVERS THE DEAL OR PROJECT TABS AT ALL" IS ONE WORD TOO STRONG,
   and `f90d708`'s message repeats the overstatement in a line that cannot be
   edited.** The PROJECT tab was genuinely untouched -- no spec navigated to a
   project's Mail tab before `e2e/rail-compose.spec.ts`. The DEAL tab was not:
   `e2e/mail.spec.ts`'s "carries the deal-linked thread to the second user"
   journey opens one. What it does there is read the THREAD LIST as a second
   user; it never presses Compose, so no test had ever built a seed from either
   tab, which is the claim that holds. The file's own header carries the
   corrected version.

5. **`f90d708`'s LIB COMMENT JUSTIFIED ITS ONE DEVIATION WITH A FALSE
   MEASUREMENT.** It said `fetchStatus` reads "idle" for one commit after a
   chained key goes live, so a gate on it would flicker open, and used that to
   depart from `pages/deal-detail.tsx`'s `defaultsInFlight`. Measured against
   the installed @tanstack/query-core 5.101.4, driving a QueryObserver through
   `useBaseQuery`'s own per-render sequence with the key flipping `"" ->
   "contact-1"`: `fetchStatus` is already `"fetching"` on that very render,
   because `getOptimisticResult` applies `fetchState()` when `_optimisticResults`
   is set. **There is no flicker.** The deviation was retired rather than
   re-argued: the gate now reads `fetchStatus`, like its neighbour.

6. **TWO STATES THE FIRST VERSION GOT WRONG, both measured.** Offline,
   `networkMode: "online"` PAUSES a fetch -- `fetchStatus: "paused"`,
   `isPending: true`, `isError: false`, queryFn never called -- so the
   `isPending` gate sat at "resolving" for ever with no error to escape
   through, which is the dead-button shape v1.1.0 rejected, reachable because
   `deal-detail.tsx` mounts the rail inside its `isLoading` branch. And a query
   whose REFETCH fails keeps its data while reporting `isError`, so the alert
   was painted beside a composer that went on to seed correctly -- once per
   transient 500 on a tab refocus, given `staleTime: 10_000`. A hop now counts
   as usable when it holds data, and paused counts as stalled.

7. **THE `enabled` FLAG WAS INERT AND WAS DELETED.** A disabled query reports
   exactly what an unasked one does -- no data, `fetchStatus: "idle"`, no error
   -- so with both predicates requiring a REASON the flag changed nothing:
   measured, forcing it true on all four hops left every journey green and only
   the source guard that existed to protect the flag went red. Restating
   `queries.ts`'s `enabled: id !== ""` across a module boundary bought nothing,
   so the coupling was removed rather than guarded. Drift is caught
   behaviourally in both directions: enabling `useContact` on an empty id takes
   down two journeys, disabling it takes down seven.

8. **A RETRY, BECAUSE TYPING AN ADDRESS RECOVERS ONLY HALF THE SEED.**
   `context.companyName` and `contactName` feed the merge placeholders and
   cannot be typed anywhere, so a failed hop left a page reload as the only
   repair. `rail/timeline.tsx` and `rail/meetings.tsx` both pair this alert with
   this control; this one now does too, scoped to the stalled hops because
   `refetch()` on a disabled query goes to the network anyway (measured: queryFn
   calls 0 to 1), which would have sent `GET /contacts/` from every deal with no
   contact.

9. **AND THE JOURNEY WRITTEN TO COVER THE GATE'S ORDER WAS ITSELF VACUOUS.**
   Its first version asserted disabled, pending, alert hidden, alert visible,
   enabled -- and `composeGate` with its two branches SWAPPED passes all five,
   because it walks the same states earlier and every assertion auto-retries for
   five seconds. Fixed by asserting what actually differs: whether the held hop
   was still on the wire at the moment the alert appeared. Second vacuous
   assertion this task has written and caught.

10. **TWO NUMBERS IN `ff46fbc`'s MESSAGE ARE WRONG, and it cannot be edited.**
    (a) "seven of which fail against this file's GRANDPARENT commit". The
    mutation that produced the seven restores `rail/mail.tsx` from **`0d184b2`**,
    which is `ff46fbc~3` -- the pre-Task-2 baseline, not the grandparent
    (`f90d708`, which already carries the fix). The seven is right; the commit
    it names is not. (b) "just three seconds earlier", of the swapped-branch
    mutation. That was measured when the company hold was 4s; the shipped
    constant is **3s** and the failing hop errors about a second in, so the gap
    is about **two** seconds. The right measurement at the wrong moment, which
    is the recurring shape this plan's conventions already name. The spec's own
    comment now states the gap against the constant rather than as a bare
    number, so it cannot go stale again.

### Task 3: Conditional blocks in the mail merge — the schedule risk

- [ ] `({{contact.pronouns}})` renders empty brackets for a contact with none. Swallowing a following space handles `Dear X Y`; nothing short of conditionals handles brackets or labels.
- [ ] **This is a template-language change wearing a bug's clothes.** The document engine already has `{{#path}}...{{/path}}`; the mail merge does not. **REUSE THE DOCUMENT ENGINE'S IMPLEMENTATION. Do not write a second one** — two template dialects in one product is worse than the empty brackets.
- [ ] v1.1.0 ruled to document the limitation rather than grow the language mid-release. **This revisits that ruling; it does not overturn it by default.** If the port is larger than it looks, **say so and defer it again with the measurement attached** rather than shipping half a language. That is a success, not a failure.
