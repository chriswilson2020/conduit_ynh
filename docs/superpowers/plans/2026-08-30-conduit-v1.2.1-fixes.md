## Conventions every task must follow

Carried from v1.2.0, where each was paid for at least twice.

- **NEVER RUN TWO MUTATING AGENTS IN ONE WORKTREE.** Reviews mutate — that is what an adversarial review is. Sequential, or one worktree each. This includes the coordinator's own commits.
- **Never restore a mutation with `str.replace("", ...)`** — an empty search string matches at position 0 and PREPENDS. Keep a copy of the original.
- **Do not `git checkout -- <file>`** to undo a mutation in a file you also edited this round.
- **Comments must be true, and a number must be measured at the moment it will be read.** v1.2.0 corrected nineteen false numbers before retiring the tally. The recurring shape was arithmetic over a moving target — the right measurement at the wrong moment, or the right set at the wrong granularity.
- **A COMMIT MESSAGE IS A COMMENT THAT CANNOT BE EDITED.** Three of those nineteen shipped in messages while the comments in the same commit were right.
- **Do not cite a line number in a file you are editing** — it rots inside your own commit. Name the passage.
- **Before committing a number, grep the file for the other places it is stated.** Two of the nineteen contradicted another sentence in the same file, written the same sitting.
- **A guard that reads source must be scoped to the construct it guards**, and its claim narrowed rather than its match widened: such a guard stops removal by omission and cannot stop tampering.
- **AN INSTRUMENT THAT HAS NEVER BEEN SHOWN TO FAIL IS NOT YET AN INSTRUMENT.** Five instruments on the v1.2.0 branch were reading something other than what they claimed. Break the thing an assertion protects and watch it fail, before trusting it to pass.
- Vitest from the repo root. Playwright locally via the hybrid loop. ASCII only. `git status` before every push. Targeted `git add`. Conventional commits with a `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer naming the model that wrote it.
- **No migration.** If a task believes it needs one, that is a finding to report.

### Task 1: The reply signature, and the guard the fix makes load-bearing

- [ ] `composer.tsx` stamps its guard key **before** discovering whether a signature exists. On a cold `useMailAccounts` — `seed.accountId` set, `sendableAccounts` still `[]`, which is the reply path — the epoch-1 pass claims the key and appends nothing, and the pass that runs when accounts arrive returns early on that key. **Stamp only once a signature has been found.**
- [ ] **THE FIX MOVES THE APPEND TO A PASS AFTER THE CARET PLACEMENT.** That is exactly what `rich-text.tsx`'s `updateSelection: false` exists to survive. Today it is load-bearing only on the account-switch path, where it is tested; after this it is load-bearing on the reply path too. **Re-verify that guard by mutation before shipping the reorder.**
- [ ] `composer.tsx`'s pending-body-focus comment asserts the append happens before the caret placement. True on a warm cache only. **Correct it with the fix.**
- [ ] A test that fails without the fix, exercising a genuinely cold cache.

#### Corrections to Task 2's premise, made while implementing it

1. **A PROJECT TAB HAS NO CONTACT HOP AT ALL, so "deal -> contact from a deal or
   project tab" is half wrong.** `rail/mail.tsx` reads `deal?.contactId` from its

### Task 3: Conditional blocks in the mail merge — the schedule risk

- [ ] `({{contact.pronouns}})` renders empty brackets for a contact with none. Swallowing a following space handles `Dear X Y`; nothing short of conditionals handles brackets or labels.
- [ ] **This is a template-language change wearing a bug's clothes.** The document engine already has `{{#path}}...{{/path}}`; the mail merge does not. **REUSE THE DOCUMENT ENGINE'S IMPLEMENTATION. Do not write a second one** — two template dialects in one product is worse than the empty brackets.
- [ ] v1.1.0 ruled to document the limitation rather than grow the language mid-release. **This revisits that ruling; it does not overturn it by default.** If the port is larger than it looks, **say so and defer it again with the measurement attached** rather than shipping half a language. That is a success, not a failure.

#### Task 3's ruling: DEFERRED A SECOND TIME, and the measurement behind it

**The two-engine layout is confirmed and there is no third call site.** Document
merge is `mergeTemplate` in `packages/api/src/services/documents-template.ts`;
mail merge is `substitutePlaceholders`/`substitutePlaceholdersHtml` in
`packages/web/src/components/mail/mail-lib.ts`. Nothing on the API side
substitutes a mail placeholder: `services/mail-templates.ts` stores and sanitises
only, `routes/mail.ts` is CRUD, and there is no server-rendered send, scheduled
mail or test helper that merges one. Every `{{` in `packages/api/src` outside the
document engine belongs to the document engine's own tests.

**THE BLOCKER IS NOT THE EXTRACTION COST, IT IS SEMANTIC INCOMPATIBILITY, AND IT
WAS MEASURED RATHER THAN ARGUED.** Every behaviour `mail-lib.test.ts` documents
was run through the real `mergeTemplate` with the most faithful nested context a
mail `TemplateContext` can build. **13 of 26 conflict.** Five root causes:

1. **An absent path renders EMPTY in documents and stays LITERAL in mail** (6 of
   the 13). `Hi {{contact.name}}` with no contact came out `Hi `. Mail's rule is
   Phase 4's -- an unfilled name stays visible so somebody notices. Preserving it
   also needs `parse` to keep each field's source text, which it discards today.
2. **A whitespace-only value is unresolved in mail** and is emitted verbatim by
   documents: `{ contactName: "   " }` gave `Hi    ` where mail leaves the
   placeholder.
3. **The one-following-space swallow has no expression in a node tree** (4 of the
   13). The space after `{{contact.salutation}}` is the first character of the
   NEXT text node, so the rule would have to live inside `render`'s hot loop --
   the quote renderer's -- rather than in a capture group.
4. **The escaper is fixed at five characters.** Mail has three modes: none for a
   subject line, three characters for a body. Measured: a contact named `O'Brien`
   renders `O&#39;Brien` into a subject header.
5. **`mergeTemplate` throws** `TemplateError` from three bounds and on a
   self-nested block; `composer.tsx`'s `applyTemplate` has no `try`/`catch`, so a
   template with one typo would take the composer down instead of printing it.

**AND THE ONE THAT DECIDES IT: mail's central rule has no block form.** Blanking
is what a composer does when it KNOWS the contact; the Inbox knows none and leaves
the placeholder visible, a distinction v1.1.0 paid for with a live defect. Asked
what `{{#contact.pronouns}}...{{/contact.pronouns}}` should do with no contact in
scope, all three answers are new language decisions: render the body (`Dear ()`,
the same defect), skip it (the v1.1.0 defect at block granularity, and it deletes
the author's literal text too), or emit the block source verbatim into a draft the
user may send. The document engine cannot answer, because its context always
carries `org`/`document`/`lines` and the state does not arise. **So the port
cannot be a port. It has to invent dialect, which is the outcome the spec and the
brief both forbid** -- and it would do so inside the function that renders every
quote PDF.

**The cost, for the record, had the semantics been compatible:** **525 lines** of
`documents-template.ts` relocated to `packages/shared` -- the `MERGE FIELDS` section
through `mergeTemplate` is 489, plus the 36 of `documentTemplateWarnings` and
`documentTemplateErrors`, which call `parse` and travel with it. The sanitiser half
stays, since it needs `sanitize-html` and shared depends on nothing but zod, and
`prepareDocumentHtml` stays with it because it composes the two.
`documents-template.test.ts` splits: 45 merge-side `it` declarations of its 86 move,
and the 10 in the `prepareDocumentHtml` tail cannot. 5 API files import the moved
symbols. `mail-lib.ts`'s substitution is rewritten and the **19** `it` declarations
across its two substitution describes with it. `composer.tsx` gains an error path,
the Settings page has to teach block syntax, and a byte-identical PDF proof covers
the lot. Roughly 14 files and two package boundaries, in a patch release, for one
cosmetic defect.

**TWO OF THOSE NUMBERS ARE WRONG IN `0a246b9`'S MESSAGE, WHICH CANNOT BE EDITED.**
(a) It says **489** lines relocate. That is the merge engine through `mergeTemplate`
and it omits the two template-linting exports below it, which call `parse` and
cannot stay behind; the figure is **525**. (b) It says **20** substitution cases are
rewritten. 20 came from counting `it(` unanchored over a hand-picked line range that
ran past `substitutePlaceholdersHtml` into `templateSubject`; bounded by the two
describes it is **19**, of which 18 predate this commit. Both are the shape this
plan's conventions already name -- the right measurement at the wrong granularity --
and both were caught by re-measuring before the report rather than by anything
failing. The merge-side counts (86, 45, 31, 10) were re-derived and hold: they count
`it` DECLARATIONS, ten of which sit inside loops and run more than once.

**Corrections to the brief, with evidence.**

1. **THERE ARE NO SEEDED MAIL TEMPLATES, so the middle option had no target.**
   `0004_bitter_excalibur.sql` creates `email_templates` and inserts nothing, and
   no migration or code path ever inserts a row. Every mail template in an install
   was typed by a person in Settings. (The seeded template is the DOCUMENT one.)
   Nothing here touches a migration.
2. **THE SANITISER IS NOT AN OBSTACLE, WHICH IS THE FAVOURABLE DIRECTION.** Block
   syntax was measured through the real `sanitizeMailHtml`: `{{#path}}`, `{{^path}}`
   and `{{/path}}` survive byte-identically, including across a paragraph boundary
   and across `<strong>`. The `&nbsp;` decode v1.1.0 found still happens, but inside
   a block body, where it is inert. The deferral does not rest on this.

**What shipped instead**, and it is a documentation fix rather than a half-language:
the Settings page's three claims about empty fields now render from `MERGE_EXAMPLES`
in `mail-lib.ts` rather than being typed beside it -- the shape `PLACEHOLDER_KEYS`
already uses for the field list, which those claims were not covered by. **One of
them was wrong by omission**: it said an empty salutation removes itself, without
saying that only happens where a contact is in scope, so an author composing from
the Inbox would watch it not happen. That case is now stated and pinned.

### Task 4: The GIF undercharge, and the real intermittent rates

- [ ] A 37-byte GIF whose logical screen descriptor disagrees with its frame data under-declares its size to the logo limit. **Fall back to the screen descriptor's dimensions instead of returning `null`** on those four shapes.
- [ ] **The ceiling held** — worst variant at 59% of the 512MB kernel limit, the other three stopped outright. This is hardening; do not describe it as an open hole.
- [ ] **Harvest the real intermittent rates. This is arithmetic on logs that already exist**, not instrumentation: Playwright runs `retries: 2` on CI and a retried failure IS reported — run `33311033649` carries a `flaky` line. Nobody has aggregated them, and a run containing a flake is green.
- [ ] Report a **number per intermittent** — Dovecot IDLE burst, phone kanban `addStage`, `crm.spec.ts` "Other…" caret — across every run on `main` and the merged phase branches. **Measure; do not fix.** A recommendation per intermittent, with its rate.

#### Corrections to Task 4's premise, made while implementing it

1. **THE BOUND IS NOT IN `documents-render.ts`.** That file carries the comment
   naming the case and the kernel limit that held; `gifSize`, `imageDataUriSize` and
   `renderInputCost` all live in `packages/shared/src/index.ts`, which the WEB bundle
   imports too (`pages/settings-org.tsx` calls `logoDataUriProblem`). So the fix is
   not API-only. The stylesheet still does not move -- rebuilt on the dev server,
   `index-M5teG3jg.css`, 33,259 bytes, sha256 `3031a0c4...d90e2`, byte-identical.

2. **THE FOUR SHAPES ARE ONE SHAPE, AND IT IS NOT "THE TRAILER CHECK".** Measured
   against Pillow 12.3.0 on the same bytes: Pillow opens a GIF if and only if the
   walk reaches an image descriptor, because `GifImageFile._open` scans for the first
   `,` and raises EOFError without one. Of the six ways `gifSize` could answer null,
   Pillow refuses five and opens one. All four v1.0.1 variants are that one. So the
   fallback is conditional on having reached a frame rather than unconditional, which
   keeps the logo upload's "no image library could open it either" refusal true --
   and that sentence was FALSE of GIF before this change, which is the defect.

3. **"CHARGED 37 x 8,256 = 305,472" IS WRONG IN `shared/src/index.ts`, in a comment
   whose own last line says why.** The charge is per CHARACTER of the payload as
   written; 37 bytes is 52 base64 characters, so it was 429,312. The backlog's copy
   of the same finding has 429,312 and is right. Corrected with the fix; the
   conclusion never depended on it, since both figures are under 2.7% of the cap.

4. **AND THERE IS A FIFTH SHAPE, WHICH THE PRESCRIBED FIX WOULD HAVE MISSED AND
   PARTLY MADE WORSE.** Hide a 13000x13000 frame behind one byte that is not a block
   introducer: the screen descriptor still says 1x1, so "fall back to the screen
   descriptor's dimensions" reads it as 1x1 and charges ONE pixel, where Pillow skips
   the byte -- its scanner resyncs -- and opens the file at 169 megapixels. Today
   that file is charged per character, so the 27-byte form is already accepted
   (297,216 pixels) and the 2,026-byte form is refused; the naive fallback would have
   made the padded form acceptable too. **This is the shape v1.0.1 spent five rounds
   on: an accounting fix bypassed by the next variant.** So the walk resyncs the way
   Pillow's does, and both forms are now charged 169,000,000 and refused.

5. **THE ORDER OF WORK IN THE BRIEF WAS RIGHT AND IS WORTH KEEPING**: "verify the
   four shapes before fixing" is what turned up 2, 3 and 4. Every expected size in
   `index.test.ts`'s new cases is what Pillow answered for those exact bytes, and a
   600-case fuzz corpus was run both ways -- 227 of them open in Pillow; the old code
   under-charged 213 and the new one under-charges none.

since a run there is as much a trial as any other.

**Recommendations, in the order they earn attention:**

1. **Dovecot IDLE burst -- SCHEDULE IT.** It is the only one with a real number and
   the only one that turns CI red, because vitest sets no retries. At 4 in 177 a
   branch of 14 pushes has a **27%** chance of going red at least once, and it takes
   about 30 pushes to reach even odds -- so "it will probably not fire this release"
   is true and is not much comfort. Two of its four firings were re-run into a green
   tick, so the visible history understates it by half, and the release checklist's
   "re-run and SAY SO" is already load-bearing. The four failures saw 11, 16, 17 and 11 of the 20
   messages, never 0 and never a wedged wait -- so whatever this is, it is a partial
   view rather than a lost wake. `walkToEnd` stops as soon as one `fetchNewer` returns
   fewer than the batch size, on the idler's own connection, the instant the wake
