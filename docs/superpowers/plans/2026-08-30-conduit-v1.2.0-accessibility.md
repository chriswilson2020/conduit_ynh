## Conventions every task must follow

Each of these cost a CI round or a review finding in Phase 7 or v1.1.0.

- **Migrations are generated, never hand-written, and NEVER `drizzle-kit push`.** Revising an unshipped one means regenerating it, restoring the journal's `when`/`tag`, verifying the journal diff is empty, and **dropping and recreating `conduit_test`** — the migrator skips by timestamp.
- **`drizzle-kit generate` splits statements on a bare `;`, including inside a string literal.**
- **Zod is the gate; the CHECK is the backstop.**
- **A raw NUL byte turns a source file binary and every tool then lies to you** — `grep -rn` returns nothing for that file and `git diff` says "Binary files differ" even with `--text`. The Edit tool round-trips one faithfully, so it recurs. **Detect with `od -c` or `grep -clP '\x00'`, never plain `grep`.**
- **Never restore a mutation with `str.replace("", ...)`.** An empty search string matches at position 0, so it PREPENDS rather than inserts and silently corrupts the file. Task 1 did this to `row-link.ts` and caught it only because the result would not parse. Restore by re-editing the exact text, or by keeping a copy of the original.
- **Do not `git checkout -- <file>` to undo a mutation experiment in a file you also edited this round** — it reverts to HEAD and silently discards your real work.
- **A version-specific representation is not a property.** Assert what a thing means, not how one version encodes it.
- **Comments must be true.** If you write a number, measure it. This project has corrected false measured numbers **fifteen** times, the most recent being Task 1's own (see its third bullet). Task 1's review round then corrected four further figures WITHIN that correction -- a margin, an x-coordinate, a pixel delta and a commit message -- which is the actual lesson: the first measurement of a thing is usually wrong, so measure it where the reader can check you.
- **Tailwind v4 scans class names in prose**, including in `.md` and config files under `packages/web` — a class in a comment is emitted as CSS and moves the stylesheet hash. `lib.test.ts`'s guard catches hyphenated tokens only; bare English words are uncatchable, so **measure the hash**.
- **`documentElement.scrollWidth` is blind to page-content overflow** and has been since the first web commit, at every viewport — a scroll container does not propagate, and neither does a clip. Measure `main`, and **prove the instrument** by injecting an over-wide probe before trusting a reading.
- Vitest from the repo root. `CONDUIT_REMOTE_DIR=/home/chris/conduit-phase4 ./scripts/remote.sh '<cmd>'`, EXPLICIT on every server call. Playwright runs locally via the hybrid loop (Phase 7 Task 6's DONE block). ASCII only. `git status` before every push. Targeted `git add`. Conventional commits, `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 1: Entity rows become keyboard-operable — the largest item

**The finding was recorded as a screen-reader gap and that undersells it.** The rows in every entity list — companies, contacts, projects, pipelines, my tasks — have no role, no accessible name and **no tab stop**, so nobody can open a record from the keyboard, at a desk or on a phone. Phase 6 recorded them as keyboard-inert before the responsive work and worse after it, because at phone width they also lose their table semantics.

- [ ] **Make a row what it already behaves like: a link to the record.** Navigation is what it does, so an anchor is the honest element and it brings a tab stop, Enter, middle-click and open-in-new-tab — none of which the current click handler supports. A button gives the tab stop and loses the rest.
- [ ] **The visual result must not change**, at either width.
- [ ] **The desktop table semantics must survive.** A row is a `<tr>` at desk width and a card below the breakpoint; the link has to live inside both without breaking either.
- [ ] ~~**119 e2e tests click these rows.**~~ **CORRECTED BY TASK 1, and it is the fifteenth false measured number in this project. Exactly TWO e2e tests click one of these rows**, both on companies: `crm.spec.ts:54` at 1280 and `mobile.spec.ts:169` at 390. Two further places locate a contacts row and assert its text without clicking; nothing clicked a projects, pipelines or task row at all. 119 is the size of the whole suite. **The suite must still pass unchanged** -- that part stands -- but read the regression net as two clicks on one list, not as broad coverage. **A test that needed LOOSENING is a signal the change went too far.**
- [ ] **AND BECAUSE THE NET IS THAT THIN, the two clicks are fixture-dependent.** Playwright clicks an element's CENTRE. Shrinking the overlay to the first cell **is** caught by `crm.spec.ts:54` -- but only because that fixture's names are short. Re-measured at 1280 with one row rendered, row-relative x: `Acme <runid>` (13 chars) ends its first cell at **428** against a centre of **503**, so the centre lands on the cell and the click does not navigate; **25 characters** already pushes the cell to 534 and the mutation goes unseen; this task's deliberately wide fixture reaches 715. So the margin is **75px of fixture length, not a guard**. `e2e/row-links.spec.ts` (added by Task 1) does not depend on it: its fixture is wide enough that the centre falls inside the name cell, it asserts that before probing, and it probes the row's far edges. **A CORRECTION TO `1a07a3e`'s COMMIT MESSAGE**, which claimed the centre still answers the anchor under the mutation "so crm.spec.ts passes on a mutation that breaks most of the row": that is false and was the wide fixture's reading attributed to the short one. The comments that commit landed in `row-links.spec.ts` and `row-link.ts` had it right; only the message was wrong, and a pushed message cannot be edited, so the correction lives here.
- [ ] Verify with the keyboard, not by reading: tab to a row and press Enter, at 1280 and 390, on at least two lists.

### Task 3: Closing a dialog leaves focus on `<body>`

Pre-existing, visible at a desk as well as a phone, affecting the task drawer, the composer and both settings dialogs.

- [ ] **Find the cause before fixing it.** Radix restores focus to the trigger by default, so something is overriding or unmounting it. Do not focus something plausible on close and call it done — a workaround will paper over whatever is also causing it elsewhere.
- [ ] Note that v1.1.0 added `onCloseAutoFocus` forwarding to `ui/select.tsx` for the contact pickers. That is a Select, not a Dialog, but it is the same family of problem and worth reading first.
- [ ] Assert focus lands on the trigger, not merely that it is not `<body>`.

### Task 4: The intermittent, which is now reproducible

Four sightings across two phases, **never once failing CI**. Phase 7 measured **1 failure in 12 runs idle, 8 in 12 with a second vitest process running** — contention amplifies a real race rather than causing it.

- [ ] **Two hypotheses are already dead and both are recorded**: it is not `waitFor`'s 10s deadline (vitest's own 5000ms fires first, so that label can never appear) and it is not a slowdown (the case costs 180-240ms and instead **wedges**).
- [ ] **Named next suspect, untested:** `ManualClock.wait(ms <= 0)` resolving without registering a pending entry, so a `waitFor(() => clock.pendingCount() > 0)` waits for something that has already happened.
- [ ] **The fix must be deterministic, not a longer timeout.** That file owns a `ManualClock`, and a wall-clock deadline inside a test that controls its own clock is the defect. If the named suspect is wrong, **say so and report what it is instead** — a second falsified hypothesis with evidence is a good outcome.
- [ ] **Two more intermittents surfaced during v1.1.0 and are related work, not yours unless they are the same bug**: `mail-integration.test.ts`'s Dovecot IDLE burst (17 of 20 messages), and `e2e/mobile.spec.ts`'s phone kanban `addStage` (once in eight runs; note `board.tsx:613` put a sticky strip directly above that button in v1.1.0, so "pre-existing" is not established). Say whether any share a mechanism.

### Task 4b: the touch-floor assertions are blind to clipping

Folded in from the backlog because it is this phase's shape: an interaction correctness
gap that reads as coverage.

- [ ] `documents.spec.ts:647,664,711,747,758,763,765` assert
      `boundingBox().height >= TOUCH_FLOOR_PX`. **A bounding box exists whether or not the
      control is on screen**, so with `<main>` clipping below the breakpoint a control
      clipped entirely off-screen still passes. The assertion that was meant to cover that
      was one of the three vacuous overflow checks v1.1.0 found.
- [ ] Assert the control is actually reachable, not merely sized — `toBeInViewport()` is
      stronger under a clip (IntersectionObserver respects ancestor clipping) and is the
      obvious instrument. Whatever you choose, **prove it**: a control moved off-screen must
      fail it.
- [ ] `touch-floors.test.ts` is a source-reading guard and is a different question — it
      pins that the classes are present. Leave it; the gap is the e2e half.
