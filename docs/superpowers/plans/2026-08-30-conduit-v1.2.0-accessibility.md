## Conventions every task must follow

Each of these cost a CI round or a review finding in Phase 7 or v1.1.0.

- **Migrations are generated, never hand-written, and NEVER `drizzle-kit push`.** Revising an unshipped one means regenerating it, restoring the journal's `when`/`tag`, verifying the journal diff is empty, and **dropping and recreating `conduit_test`** — the migrator skips by timestamp.
- **`drizzle-kit generate` splits statements on a bare `;`, including inside a string literal.**
- **Zod is the gate; the CHECK is the backstop.**
- **A raw NUL byte turns a source file binary and every tool then lies to you** — `grep -rn` returns nothing for that file and `git diff` says "Binary files differ" even with `--text`. The Edit tool round-trips one faithfully, so it recurs. **Detect with `od -c` or `grep -clP '\x00'`, never plain `grep`.**
- **Never restore a mutation with `str.replace("", ...)`.** An empty search string matches at position 0, so it PREPENDS rather than inserts and silently corrupts the file. Task 1 did this to `row-link.ts` and caught it only because the result would not parse. Restore by re-editing the exact text, or by keeping a copy of the original.
- **Do not `git checkout -- <file>` to undo a mutation experiment in a file you also edited this round** — it reverts to HEAD and silently discards your real work.
- **NEVER RUN TWO MUTATING AGENTS IN ONE WORKTREE AT THE SAME TIME. Coordinator's rule,
  written after the coordinator broke it.** Task 3's two adversarial reviewers were
  dispatched concurrently. Both mutate source to test guards -- that is what an adversarial
  review IS -- and one of them watched `dialog-focus.ts` change under it twice mid-read.
  Those edits were the other reviewer's unit mutations. Both restored correctly and the tree
  ended clean, so nothing was lost; what was lost was the meaning of every measurement either
  of them took, and **neither could have known which of its readings were contaminated**.

  This is the third hazard on this list whose shared resource is THE WORKTREE, after the
  `checkout --` above and the `replace("", ...)` before it. The other two are things one agent
  does to itself. This one is invisible from inside the agent, which is what makes it the
  coordinator's to prevent: **sequential, or one worktree each.** The same applies to the
  coordinator's own edits -- a docs commit landing while an implementer holds the tree is a
  second writer, not an exception.
- **A version-specific representation is not a property.** Assert what a thing means, not how one version encodes it.
- **Comments must be true. If you write a number, measure it, and measure it at the moment
  the number will be read rather than the moment it was convenient to take.**

  **THE RUNNING TOTAL IS RETIRED AT NINETEEN, and retiring it is the finding.** This bullet
  carried a tally from Task 1 to Task 3. It went stale three times -- once within a single
  task, when Task 3 shipped a plan entry asserting the total "stood at seventeen" in the very
  commit holding its own eighteenth and nineteenth. Then Task 3's last round asked whether two
  further corrections qualified, and that question settled it: **a metric whose maintenance
  needs a ruling, and which has itself produced false numbers three times, is no longer
  measuring the thing it was made to show.** The ordinals stay where each task recorded them
  -- they are local, checkable, and carry the lesson with them. The aggregate goes.

  What the exercise established, which is worth more than the count:

  - **Every one of the last several was arithmetic over a moving target** -- a count taken
    from the right measurement at the wrong moment, or from the right set at the wrong
    granularity. Not carelessness. Task 3 cited `ui/dialog.tsx:189-192` accurately and then
    inserted six lines above it in the same commit; the round before did the same in the
    opposite direction. **A line-number citation into a file you are editing rots inside your
    own commit.** Name the passage instead.
  - **Both the eighteenth and nineteenth were counts that contradicted another sentence in
    the same file, written in the same sitting** -- "the seven working ones" ten lines under
    "ten more restore their trigger". Before you commit a number, grep the file for the other
    places it is stated.
  - **Three separate instruments on this branch were reading something other than what they
    claimed**: `document.activeElement` sampled a macrotask too early (which answers BODY for
    every dialog, working ones included), a locator that matched a board card instead of a
    search result, and a probe that registered its timer before the click it was timing. **An
    instrument that has never been shown to fail is not yet an instrument.** Prove it against
    a case that must fail before trusting a case that passes.
- **A COMMIT MESSAGE IS A COMMENT THAT CANNOT BE EDITED.** Tasks 1 and 2 each shipped a false
  number in a message while the comments in the same commit had it right -- `1a07a3e`
  attributed a wide fixture's reading to a short one, and `4f0aa24` claimed two mutation
  survivors where one exists. Nothing can repair either; both corrections live in this plan
  naming the commit. **Measure before you write a number in a message**, and prefer pointing
  at the file that carries the measurement over restating it.
- **A guard that reads source must be scoped to the construct it guards.** Task 2's first
  draft matched `event.preventDefault()` file-wide, and that string appears **six** times in
  `composer.tsx`, so the guard passed with the handler deleted. Task 2 then did it AGAIN in the
  commit that fixed it -- `container.focus();` is spelled twice in that file, so the assertion
  naming the new null-handle branch stayed green when that branch was deleted, with typecheck
  clean. **Task 1 hit this class twice** (an override and a misplacement); its third gap was a
  different animal -- an e2e COVERAGE hole, where deleting `ROW_LINK_ROW` left every browser
  test passing.

  Mutation-test every source-reading guard by deleting the thing it claims to protect. And
  **narrow the claim rather than widening the match**: such a guard stops removal by OMISSION,
  and cannot stop tampering. A rename or a misplacement is caught by `npm run typecheck`, not
  by the guard; a trailing `//` comment or a string literal satisfies it; `if (false as
  boolean)` walks straight past it. Say so in the file instead of chasing it.
- **Tailwind v4 scans class names in prose**, including in `.md` and config files under `packages/web` — a class in a comment is emitted as CSS and moves the stylesheet hash. `lib.test.ts`'s guard catches hyphenated tokens only; bare English words are uncatchable, so **measure the hash**.
- **`documentElement.scrollWidth` is blind to page-content overflow** and has been since the first web commit, at every viewport — a scroll container does not propagate, and neither does a clip. Measure `main`, and **prove the instrument** by injecting an over-wide probe before trusting a reading.
- Vitest from the repo root. `CONDUIT_REMOTE_DIR=/home/chris/conduit-phase4 ./scripts/remote.sh '<cmd>'`, EXPLICIT on every server call. Playwright runs locally via the hybrid loop (Phase 7 Task 6's DONE block). ASCII only. `git status` before every push. Targeted `git add`. Conventional commits, with a `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer **naming the model that actually wrote the commit** -- this line said `Fable 5` while every commit from `46a70b3` on says `Opus 5`, and the trailer is attribution, so it follows the author rather than the plan.
