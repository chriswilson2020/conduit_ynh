# Conduit Phase 4.2 — Mail Visibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Private-by-default mail visibility per account: a visibility predicate applied to every mail read path, owner-only IMAP moves, a per-account Private/Shared toggle — released as v0.7.0.

**Tech Stack:** No new dependencies. All Phase 4/4.1 engine and review conventions are BINDING (CONDUIT_REMOTE_DIR remote.sh; ASCII with String.fromCharCode fixtures; the three-unread-computations lesson; the skip-reason precedence types; hand-written-index rules; comment discipline: state only what was measured). > **HANDOFFS for Task 4:**
> - `not_owner` is always a whole-thread SKIP (`ok: true, skipped: true`), never a failure — and a mixed-ownership thread reports plain `{ok: true}`: the per-thread answer never mentions an unowned remainder. Its copy should read as "only the mailbox owner can archive or trash — Hide in CRM is available to everyone" (the spec's Move rights line).
> - `not_found` now legitimately appears in bulk results for threads the viewer just saw (an account flipped back to private mid-session). Client copy must not distinguish it from a deleted/unknown thread — tests pin byte-equality with the nonexistent answer.
> - `archived_account` can describe someone else's account (it outranks not_owner): its copy must not say "your account" or point the viewer at their own Settings.
> - The toggle's widened frame reaches the list, badge and per-folder counts but NOT `["mail-thread", <id>]` (different first key segment — TanStack prefix matching, see queries.ts's own by-folder nesting comment), and the conversation pane renders off the URL param independently of the list. So another user's OPEN pane keeps showing a flipped-to-private thread from cache until its next focus refetch (staleTime 10s + refetchOnWindowFocus). Bounded, no server-side leak (only already-delivered bytes), and unavoidable for those bytes — but Task 4 must DECIDE: accept-and-document, or close the pane when its thread leaves the list. Separately: a same-value submit produces no echo frame, so the optimistic-off form must not wait for one.
> - `ownedByViewer` gates the Archive/Trash controls, but owned does not guarantee eligible (archived/awaiting rows still skip) — the per-thread reasons remain the backstop the disabled-state copy falls back to.
> - The ownedByViewer FOLDER-SCOPE trap: the flag is thread-global (`bool_or` over the thread's visible messages, deliberately not folder-scoped) while moves are folder-scoped — a Projects view can show a thread `ownedByViewer: true` whose only Projects-folder rows sit on someone else's shared account, and the enabled Archive button then answers a `not_owner` skip. More likely and less intuitive than the archived/awaiting cases above: the disabled-state copy must handle a `not_owner` arriving AFTER an enabled click, not only pre-disable.
