# Conduit Phase 4.2 — Mail Visibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Private-by-default mail visibility per account: a visibility predicate applied to every mail read path, owner-only IMAP moves, a per-account Private/Shared toggle — released as v0.7.0.

**Architecture:** One column (migration 0006), one predicate pair (`inbox-visible` / `record-visible`) built once in mail-threads.ts and applied exhaustively per the spec's table, one new skip reason (`not_owner`) in the move service, one Settings toggle. Spec: `docs/superpowers/specs/2026-08-21-conduit-phase-4.2-visibility-design.md` — the authority; its predicate table is the checklist.

**Tech Stack:** No new dependencies. All Phase 4/4.1 engine and review conventions are BINDING (CONDUIT_REMOTE_DIR remote.sh; ASCII with String.fromCharCode fixtures; the three-unread-computations lesson; the skip-reason precedence types; hand-written-index rules; comment discipline: state only what was measured). Suite at start: 1472 unit + 36 integration + 46 e2e, green. Branch `worktree-phase-4.2-visibility` from the v0.6.0 tip.

### Task 3: Move rights + the Settings toggle (API side)

`mail-move.ts`: actor-ownership joins the candidate eligibility filters (BEFORE refusals, per the 4.1 ordering rule): messages on accounts the actor does not own → excluded with noted reason `not_owner`; a thread whose whole in-scope set is unowned → `{ok: true, skipped: true, reason: "not_owner"}`; mixed-ownership threads move the owned half (test). Bulk stays auth-only at the route (visibility enforced by the predicate: you cannot NAME a thread you cannot see [superseded — see the DONE block: thread ids ARE nameable, sse.ts fans `["mail-thread", <id>]` to every subscriber; the service gates visibility first, inside candidate collection] — thread ids arrive from lists the predicate already filtered; the detail-404 rule covers direct probing; comment this authz chain explicitly). `hide` unchanged (any viewer; thread-global, documented). Mark-read unchanged. `updateAccount` accepts `visibility` (owner-only as ever; NOT a connection change — wake only; flipping publishes `[["mail-accounts"]]` + `[["mail-threads"]]` + `[["mail-unread"]]` — every user's lists change). ~14 tests.

As built: the visibility gate is FOLDED into collectCandidates' requested-threads `inArray` read (`visibleThreads(actorId, "record")`, newly exported from mail-threads.ts) — an invisible id is absent from `known` exactly as a nonexistent one is, both take the same NotFoundError construction (byte-compare pinned at service AND route level, including the spec-review's no_target-label-leak probe case), and an invisible thread's messages are provably never fetched (the messages read selects by `known`). > **HANDOFFS for Task 4:**
> - `not_owner` is always a whole-thread SKIP (`ok: true, skipped: true`), never a failure — and a mixed-ownership thread reports plain `{ok: true}`: the per-thread answer never mentions an unowned remainder. Its copy should read as "only the mailbox owner can archive or trash — Hide in CRM is available to everyone" (the spec's Move rights line).
> - `not_found` now legitimately appears in bulk results for threads the viewer just saw (an account flipped back to private mid-session). Client copy must not distinguish it from a deleted/unknown thread — tests pin byte-equality with the nonexistent answer.
> - `archived_account` can describe someone else's account (it outranks not_owner): its copy must not say "your account" or point the viewer at their own Settings.
> - The toggle's widened SSE frame needs no new client handling (existing key subscriptions cover all three families), and a same-value submit produces no echo frame — the optimistic-off form must not wait for one.
> - `ownedByViewer` gates the Archive/Trash controls, but owned does not guarantee eligible (archived/awaiting rows still skip) — the per-thread reasons remain the backstop the disabled-state copy falls back to.
