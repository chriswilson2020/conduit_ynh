Add the assertion the backlog names (no entry matching `/mail/` on B's timeline). Keep it beside the existing two with a comment on what each of the three catches, since the trio is the phase's most important test.
2. **Contenteditable typed without verification** — suite-wide. The suite clicks a TipTap editor and types with no assertion that focus landed or the text arrived; a view not yet attached drops leading characters and the failure surfaces in the NEXT test with a misleading message. Fix it once, as a helper both `mail.spec.ts` and `meetings.spec.ts` use (the mail composer body and `meeting-notes` are the two sites). No exit animation is configured and CI has burned zero retries, so this is hardening: make the gate explicit (assert the option list is gone before re-opening) rather than relying on it being fast.

Playwright is CI-only: write typecheck-clean (`tsc --noEmit -p e2e` rides the root typecheck) and let CI prove them. Push and report the run.

### Task 2: web refactor — helper home and label duplication (items 5-6)

**Files:** `packages/web/src/lib.ts` (+ `lib.test.ts`), `packages/web/src/components/mail/mail-lib.ts`, `packages/web/src/components/rail/timeline.tsx`, `packages/web/src/components/rail/meetings.tsx`, `packages/web/src/components/rail/rail.tsx`, plus the mail call sites the move touches.

1. **Move the cursor-page helpers to their real home.** `mail-lib`'s `ThreadPages<T>` now serves three consumers, two of them in `rail/`, creating a rail->mail import edge that exists only because of where the code lives. Move the six symbols to `packages/web/src/lib.ts`, rename `Thread*` -> `Cursor*`, and DROP the `= MailThreadListItem` default type parameter (it exists solely to avoid touching mail call sites; make all three explicit). Move the existing tests with them. Every mail call site must read unchanged in BEHAVIOUR — a shared-helper change that silently alters the inbox would be serious, so say what you checked.
2. **Collapse the label duplication.** `userLabel` exists in three copies inside `meetings.tsx` alone — with THREE different fallbacks (`undefined`, `"..."`, `"—"`) — and nine app-wide; `meetingWhenLabel`'s `toLocaleString()` + duration composition is written twice byte-identically; `recordKey` in `rail.tsx` hand-rolls what the tested `threadFilterKey` already does; `timeline.tsx`'s actor label is a fourth spelling of `userLabel`. Extract pure, tested functions (the differing fallbacks are exactly the drift a shared function prevents — make the fallback a parameter). Reuse `threadFilterKey`/its renamed equivalent for `recordKey` or extract one shared key builder; do not leave two schemes one import apart.

Pure-lib tests only (this repo has no testing-library). Suite must stay green with no behaviour change — this task should move no user-visible pixel.

### Task 3: two UX fixes (items 4, 7, 8)

**Files:** `packages/web/src/pages/company-detail.tsx`, `contact-detail.tsx`, `deal-detail.tsx`, `project-detail.tsx` (the loading-state shape), `packages/web/src/components/mail/rich-text.tsx`, `packages/web/src/components/rail/meetings.tsx`.

1. **The cold-navigation rail remount** (the one with real user impact). A detail page's bare `if (isLoading) return <p>Loading...</p>` REPLACES its frame, so most real cross-record navigations remount the rail, dropping tab state and the meeting selection by accident — the record-keyed guard only does work between two records already cached. Fix the class: render a detail page's loading state INSIDE its frame rather than in place of it. Check all four detail pages; keep the change minimal and consistent. This is user-visible: state the before/after behaviour in the commit.
2. **Dead links in rendered meeting notes.** `openOnClick: false` is right for the editor and wrong for the read-only view, so a URL in meeting notes renders underlined and does nothing. Give `RichTextView` working links (and decide, stating why, whether they open in a new tab — these are notes the user wrote themselves, not mail from strangers). `RichTextView` also takes no `ariaLabel`, unlike `RichTextEditor`, so the notes region is unlabelled — fix that too.
3. **`OwnerSelect`-as-attendee-picker -> a real `UserPicker`.** Correct today (the pinned-value trick was verified against Radix's `useControllableState`), but a `role="combobox"` reporting a value that never changes is the wrong primitive, and already-added colleagues stay in the option list so re-picking produces an error banner instead of simply not being offered. Build the ~20-line `UserPicker` on the same `Select*` primitives, filtering already-added ids — which also lets `unassignedLabel` come back out of the shared field component. Note that `meetings.tsx`'s `if (userId === null) return;` is currently UNREACHABLE (Radix suppresses the callback when value === prop); the new shape should make that guard either real or unnecessary. Keep the `meeting-add-user` testid — e2e locates it.
